## 💡 Ключевые решения (чтобы не забыть)

| Решение | Почему |
|---|---|
| SQLite для локальной работы | Простота, не требует сервера, файл-база |
| PostgreSQL для production | Полная схема, 34 таблицы, надёжность |
| `cost_price_synthetic = price × 0.7` | Искусственная себестоимость, пока нет реальных закупок |
| `cost_price_at_sale` в `posting_item` | Точная маржа на момент продажи (цены менялись) |
| Компенсация остатков (`fix_initial_stock`) | Чтобы не уходить в минус после загрузки истории |
| Минимизация ПД (никнейм, город, возраст) | Снижение риска 152-ФЗ |
| Два контура (закупка / продажа) | Независимое развитие, пересечение только через `stock` |
| `HISTORY.md` как инструкция | Перед «зависающим» шагом — обновить, потом действовать |

## 📝 Как обновлять этот файл

1. При завершении крупного этапа — добавить новую запись **сверху** (после заголовка).
2. Обновить «Текущий статус» (что работает / что нет).
3. Обновить «Ближайшие шаги».
4. Если появилось новое ключевое решение — добавить в таблицу.
5. **Перед рискованным шагом** — дописать запись «Начинаю: <что делаю>», чтобы при обрыве было понятно, где остановились.

**Формат записи:**
```markdown
## YYYY-MM-DD — Краткое название

- Что сделано (список)
- Что загружено (цифры)
- Что сломано / проблемы
- Решения (если были)
```
