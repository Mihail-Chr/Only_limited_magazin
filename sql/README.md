# База данных (db)

Файл SQLite-базы. **Не коммитить в Git** (содержит реальные данные).

## Файл

`only_limited.sqlite3` — SQLite-база со всеми таблицами и данными.

## Структура

Таблицы соответствуют модели данных (см. `docs/04_модель_данных.md` и далее), но в упрощённом виде для SQLite. **Полный список таблиц — в `src/schema.sql`**.

### Основные таблицы

- **`warehouse`** — склады (код, название, валюта по умолчанию).
- **`warehouse_currency`** — поддерживаемые валюты на складе (M2M).
- **`store`** — магазины (маркетплейсы), с `client_id`, `api_key`, `has_api`.
- **`app_user`** — пользователи (логин, email, хеш пароля).
- **`role`** — роли (`admin`, `warehouse_keeper`, `seller`, `auditor`).
- **`user_role`** — связь пользователей и ролей (M2M).
- **`user_warehouse`** — связь пользователей и складов (M2M, кладовщик может быть на нескольких складах).
- **`user_store`** — связь пользователей и магазинов (M2M, продавец привязан к магазину).

### Товары и цены

- **`product`** — карточки товаров (артикул `offer_id`, название, бренд, платформа, жанр, габариты, фото, себестоимость `cost_price_synthetic` / `cost_price_real`, `avg_market_price` для будущего).
- **`listing`** — публикации товара в конкретном магазине (цена, `old_price`, SKU, штрихкод, статус, ошибки модерации, `commission_rate`, `payout_amount`).
- **`stock`** — остатки на складе (quantity, `updated_at`).
- **`stock_manual`** — ручной физический остаток (вводится кладовщиком).
- **`price_history`** — история изменения цен (для аналитики).
- **`stock_history`** — история изменения остатков (для аудита).

### Заказы OZON (история продаж)

- **`posting`** — отправления (заказы FBS) с OZON (номер, статус, дата, сумма).
- **`posting_item`** — позиции отправлений (товар, количество, цена, `cost_price_at_sale` — себестоимость на момент продажи).
- **`market_offers`** — заготовка для будущего агента закупок (цены на площадках).

### Служебные

- **`sqlite_sequence`** — системная таблица SQLite для автоинкрементов (не трогать).

## Как открыть

**DBeaver:**
1. Новое соединение → SQLite
2. Путь: `db/only_limited.sqlite3`
3. Открыть

**Командная строка (sqlite3):**
```bash
sqlite3 db/only_limited.sqlite3
.tables
.schema product
SELECT COUNT(*) FROM product;
```

## Резервная копия

Перед любыми рискованными операциями (массовое обновление, миграция):
```bash
cp db/only_limited.sqlite3 db/only_limited_backup_YYYYMMDD.sqlite3
```

## Переход на PostgreSQL

SQLite — для локальной работы. При развёртывании на сервере — PostgreSQL (полная схема в `sql/01`–`04`).

**Важно:** SQLite не поддерживает пользовательские роли (как в PostgreSQL). Скрипт `sql/20_role_operator.sql` предназначен **только для PostgreSQL**. В SQLite права доступа к файлу определяются на уровне файловой системы.
