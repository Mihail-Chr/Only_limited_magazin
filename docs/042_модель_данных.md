# Модель данных — часть 3: Закупка

Версия: 1.0
Статус: Черновик
Последнее обновление: 2026-10-23

Продолжение `04_модель_данных.md` (часть 1) и `041_модель_данных.md` (часть 2). Здесь — контур закупки.

> **Ключевые принципы:**
> - **Заказ — подсущность посылки.** 1 `PurchaseOrder` → 1 `Shipment` (FK `shipmentId` в `purchaseOrders`). 1 `Shipment` → N `PurchaseOrder`.
> - **Одна история статусов — у посылки** (`shipmentStatusHistory`). У заказа своей истории нет.
> - **`orderDate` — на уровне заказа** (дата оплаты, предоплата). У посылки статуса `paid` нет — начинается с `at_carrier`.
> - **Все суммы — в валюте заказа** (`currencyId` в `purchaseOrders`).
> - **Одна посылка = одна валюта.** Мультивалютных посылок нет.
> - **`landedCost*` не хранится в позициях** — вычисляется при приёмке, сразу идёт в `stock.avgCost*`.
> - **`totalAmount` не хранится** — вычисляется по позициям.
> - **`quantityReceived`** — результат приёмки. История приёмок — фаза 2.
> - **4 ключевые даты:** `orderDate` (поле), `at_carrier`, `shipped`, `received` (из истории посылки).

## 3. Закупка

### 3.1. `purchaseOrders` — Заказы на закупку

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `purchaseOrderId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `sellerId` | `SMALLINT` | `NOT NULL`, `REFERENCES sellers(sellerId)` | — | Поставщик |
| `currencyId` | `SMALLINT` | `NOT NULL`, `REFERENCES currencies(currencyId)` | — | Валюта заказа (JPY, USD, EUR) |
| `orderDate` | `DATE` | `NOT NULL` | — | **Дата оплаты (начала заказа).** Предоплата |
| `externalNumber` | `VARCHAR(50)` | | — | Номер заказа у поставщика. `NULL` — неизвестен |
| `shipmentId` | `INTEGER` | `REFERENCES shipments(shipmentId) ON DELETE RESTRICT` | — | Посылка. `NULL` — пока не привязан |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создан |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменён |

**Индексы:** PK, `INDEX (sellerId)`, `INDEX (currencyId)`, `INDEX (shipmentId)`, `INDEX (orderDate)`.

**Бизнес-правила:**
- `orderDate` — **дата оплаты.** Одна из 4 ключевых дат.
- `currencyId` — валюта заказа. Все суммы в позициях — в этой валюте.
- `shipmentId = NULL`, пока не привязан. При привязке — валюта заказа = валюта посылки.
- Сумма заказа не хранится — вычисляется по позициям.

### 3.2. `purchaseOrderItems` — Позиции заказа

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `purchaseOrderItemId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `purchaseOrderId` | `INTEGER` | `NOT NULL`, `REFERENCES purchaseOrders(purchaseOrderId) ON DELETE CASCADE` | — | Заказ |
| `goodId` | `INTEGER` | `NOT NULL`, `REFERENCES goods(goodId) ON DELETE RESTRICT` | — | Товар |
| `quantityOrdered` | `INTEGER` | `NOT NULL`, `CHECK (quantityOrdered > 0)` | — | Заказанное количество |
| `quantityReceived` | `INTEGER` | `CHECK (quantityReceived >= 0 AND quantityReceived <= quantityOrdered)` | — | Фактически полученное. `NULL` — не принято |
| `supplierPrice` | `NUMERIC(12,2)` | `NOT NULL`, `CHECK (supplierPrice >= 0)` | — | Цена за единицу (в валюте заказа) |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменена |

**Индексы:** PK, `INDEX (purchaseOrderId)`, `INDEX (goodId)`, `INDEX (quantityReceived)`.

**Бизнес-правила:**
- `quantityReceived` — `NULL`, пока приёмка не проведена. При приёмке заполняется. История приёмок — фаза 2 (`receipts`).
- `landedCost*` не хранится — вычисляется при приёмке.
- При пересортице — `quantityReceived` корректируется по позициям.

### 3.3. `shipments` — Посылки

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `shipmentId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `trackNumber` | `VARCHAR(100)` | | — | Трек-номер. `NULL` — не присвоен. **Не уникален** — у разных служб разные форматы |
| `carrierId` | `SMALLINT` | `REFERENCES carriers(carrierId)` | — | Служба доставки (DHL, FedEx, EMS) |
| `originCountryId` | `SMALLINT` | `REFERENCES countries(countryId)` | — | Страна отправки (США, Япония). Может отличаться от `sellers.countryId` |
| `currencyId` | `SMALLINT` | `NOT NULL`, `REFERENCES currencies(currencyId)` | — | Валюта посылки (для `deliveryCost`, `customsDuty`). Совпадает с валютой всех `purchaseOrders` |
| `deliveryCost` | `NUMERIC(12,2)` | `CHECK (deliveryCost >= 0)` | — | Стоимость доставки всей посылки (в валюте посылки). `NULL` — неизвестна |
| `customsDuty` | `NUMERIC(12,2)` | `CHECK (customsDuty >= 0)` | — | Сумма пошлины (в валюте посылки). `NULL` — неизвестна |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана (дата формирования в системе) |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменена |

**Индексы:** PK, `INDEX (trackNumber)` (без UNIQUE), `INDEX (carrierId)`, `INDEX (originCountryId)`, `INDEX (currencyId)`.

**Бизнес-правила:**
- `trackNumber` — не уникален. Уникальность в рамках службы — фаза 2 (`UNIQUE (carrierId, trackNumber)`).
- `carrierId` — служба доставки. Опционально.
- `originCountryId` — страна отправки (склад посредника). Для логистической аналитики. Может отличаться от страны регистрации продавца.
- `currencyId` — валюта посылки. Все `purchaseOrders` в посылке — та же валюта.
- **Поля дат (`shipDate`, `customsDate`, `receiveDate`) отсутствуют.** Даты — в `shipmentStatusHistory`.
- `createdAt` — дата «посылка сформирована в системе». Не путать с `at_carrier` (физическое поступление в СД).

### 3.4. `shipmentStatusHistory` — История статусов посылки

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `historyId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `shipmentId` | `INTEGER` | `NOT NULL`, `REFERENCES shipments(shipmentId) ON DELETE CASCADE` | — | Посылка |
| `statusId` | `SMALLINT` | `NOT NULL`, `REFERENCES statuses(statusId)` | — | Статус (`statusType = 'purchase'`) |
| `statusDate` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда установлен (дата события) |
| `comment` | `TEXT` | | — | Комментарий. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда запись создана |

**Индексы:** PK, `INDEX (shipmentId, statusDate)`, `INDEX (statusId)`.

**Статусы посылки:**

| № | `statusName` | Что означает | Ключевая дата |
|---|---|---|---|
| 1 | `at_carrier` | Поступила в СД (на СВХ) | **Дата поступления в СД** |
| 2 | `shipped` | Отправлена, трек присвоен | **Дата отправки** |
| 3 | `customs` | На таможне | — |
| 4 | `out_for_delivery` | В доставке (опц.) | — |
| 5 | `received` | Получена | **Дата получения** |

**Бизнес-правила:**
- История начинается с `at_carrier`. Статуса `paid` нет (даты оплаты — в `purchaseOrders.orderDate`).
- При смене статуса — новая запись. Старые не удаляются.
- Текущий статус = последняя запись по `statusDate`.

---

### 3.5. Связь `purchaseOrders` ↔ `shipments`

Через FK `shipmentId` в `purchaseOrders`:
- 1 `PurchaseOrder` → 1 `Shipment` (жёсткое правило).
- 1 `Shipment` → N `PurchaseOrder` (консолидация).

Промежуточная таблица не нужна. После привязки менять `shipmentId` не рекомендуется.

### 3.6. `shipmentLosses` — Потери посылок

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `lossId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `shipmentId` | `INTEGER` | `NOT NULL`, `REFERENCES shipments(shipmentId) ON DELETE RESTRICT` | — | Посылка |
| `lossType` | `VARCHAR(10)` | `NOT NULL`, `CHECK (IN ('full','partial'))` | — | Полная / частичная |
| `lossDate` | `DATE` | `NOT NULL` | — | Дата фиксации |
| `reason` | `VARCHAR(50)` | `NOT NULL`, `CHECK (IN ('customs_rejected','destroyed','returned_to_seller','lost_in_transit','defect','incomplete'))` | — | Причина |
| `lossAmount` | `NUMERIC(12,2)` | `NOT NULL`, `CHECK (lossAmount >= 0)` | — | Сумма потери (в валюте посылки) |
| `refundReceived` | `NUMERIC(12,2)` | `CHECK (refundReceived >= 0)` | `0` | Сколько вернули (в валюте посылки) |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменена |

**Индексы:** PK, `INDEX (shipmentId)`, `INDEX (lossDate)`, `INDEX (lossType)`, `INDEX (reason)`.

**Причины:**

| `reason` | `lossType` | Компенсация |
|---|---|---|
| `customs_rejected` | full/partial | От поставщика/таможни (часто 0) |
| `destroyed` | full/partial | От поставщика/ТК |
| `returned_to_seller` | full/partial | Частичный возврат |
| `lost_in_transit` | full/partial | От службы доставки |
| `defect` | partial | От ТК по `supplierPrice` |
| `incomplete` | partial | От ТК по `supplierPrice` |

**Пересортица** — не loss, а корректировка `quantityReceived`.

**Распределение overhead:**
1. **Нормальная приёмка:** overhead на все позиции всех заказов пропорционально `supplierPrice × quantityReceived`.
2. **Частичная потеря:** overhead только на принятые. Потерянные не участвуют. Компенсация = `supplierPrice` потерянных.
3. **Полная потеря:** overhead не распределяется. Всё — в `shipmentLosses`.

**Убыток = `lossAmount − refundReceived`.** Не распределяется на себестоимость.

## 4 ключевые даты для анализа

| № | Событие | Где хранится |
|---|---|---|
| 1 | Дата оплаты заказа | `purchaseOrders.orderDate` |
| 2 | Дата поступления в СД | `shipmentStatusHistory` (`at_carrier`) |
| 3 | Дата отправки посылки | `shipmentStatusHistory` (`shipped`) |
| 4 | Дата получения | `shipmentStatusHistory` (`received`) |

**Аналитика:**
- Время от оплаты до СД (`at_carrier − orderDate`) — скорость поставщика + консолидация.
- Время в пути (`received − shipped`) — логистика (по `carrierId` — сравнение служб).
- Время на таможне (`customs − shipped` или `received − customs`).
- Общее время (`received − orderDate`).
