## 1. Участники (акторы)

| Актор | Роль |
|---|---|
| **Менеджер по закупкам** | Создаёт `purchaseOrders`, ведёт поставщиков |
| **Кладовщик** | Принимает посылки, заполняет характеристики, оприходует |
| **Менеджер по продажам** | Обрабатывает `salesOrders` |
| **Поставщик (Seller)** | Продаёт нам товар за рубежом |
| **Посредник / Форвардер** | Консолидирует посылки |
| **Служба доставки (Carrier)** | Транспортирует посылки, компенсирует потери |
| **Таможня** | Начисляет пошлины |
| **Покупатель (Buyer)** | Покупает у нас |
| **Маркетплейс** | Принимает заказы, платежи, доставляет, обрабатывает возвраты, платит нам |

## 2. Жизненный цикл закупки

**Триггер:** остаток ниже уровня или новый товар.

**Ключевое:** заказ — **подсущность посылки**. Одна посылка может содержать несколько заказов (консолидация). Статусы — **на уровне посылки** (`shipmentStatusHistory`).

### 2.1. Статусы посылки

`at_carrier` → `shipped` → `customs` → `out_for_delivery` (опц.) → `received`

| Статус | Что означает |
|---|---|
| `at_carrier` | Заказы поступили в СД (на СВХ), ожидание консолидации |
| `shipped` | Посылка отправлена, трек присвоен |
| `customs` | На таможне |
| `out_for_delivery` | В доставке (опционально) |
| `received` | Получена |

### 2.2. Шаги

1. Менеджер создаёт `PurchaseOrder` (продавец, валюта, `orderDate` — дата оплаты). Добавляет позиции.
2. Заказ ждёт консолидации. **`orderDate` = дата оплаты** — одна из 4 ключевых дат.
3. Когда товар поступил к посреднику → создаётся или обновляется `Shipment`. Статус → `at_carrier`. **Дата `at_carrier` — вторая ключевая дата.**
4. Посылка отправлена, трек присвоен → `shipped`. **Третья ключевая дата.**
5. Таможня → `customs`.
6. Получена → `received`. **Четвёртая ключевая дата.**
7. Кладовщик принимает товар (раздел 3).

### 2.3. Один PurchaseOrder → одна Shipment

Жёсткое правило. Промежуточная таблица не нужна. Поле `purchaseOrders.shipmentId` (nullable, пока не привязан).

## 3. Приёмка на склад

**Триггер:** посылка физически прибыла (статус `received`).

### 3.1. Переменные

**Позиция заказа:** `supplierPrice`, `quantityOrdered`, `quantityReceived`.

**Посылка:** `deliveryCost`, `customsDuty`, `totalShipmentValue = Σ(supplierPrice × quantityReceived)` по принятым.

**Склад:** `qtyBefore`, `avgCostBefore`, `qtyAfter`.

### 3.2. Расчёт landed cost

```
positionValue     = supplierPrice × quantityReceived
positionShare     = positionValue / totalShipmentValue
positionOverhead  = (deliveryCost + customsDuty) × positionShare
landedCostPerUnit = supplierPrice + (positionOverhead / quantityReceived)
```

**Пример:** 12 000 ₽ товаров, доставка 3000 ₽, пошлина 1500 ₽. Позиция A: 5 шт × 1000 ₽ = 5000 ₽ (доля 0.4167), overhead 1875 ₽, landed cost = **1375 ₽/шт**.

### 3.3. Обновление средневзвешенной в трёх валютах

Курс — на дату прихода, из `exchangeRates` (ЦБ РФ). Для каждой валюты `C`:

```
avgCostAfter(C) = (qtyBefore × avgCostBefore(C) + quantityReceived × landedCostPerUnit(C))
                  / (qtyBefore + quantityReceived)
```

`stock.avgCostUpdatedAt` = дата приёмки.

**Особые случаи:**
- Если `avgCostBefore IS NULL` (первая известная цена) — `avgCostAfter = landedCostPerUnit` (без усреднения).
- Если `quantityReceived = 0` (позиция потеряна) — `avgCost` не меняется.

### 3.4. Порядок действий

1. Сверка фактического с заказанным.
2. Заполнение характеристик (жанр, издание, регион, годы, `audience`) — **обязательно для игр**.
3. Проверка товара. Если требует подготовки — `stock.countOfRepair += N`.
4. Приёмка: расчёт landed cost, обновление `avgCost*` (раздел 3.2–3.3).
5. Заполнение `quantityReceived` в позициях.

**Приёмка = обновление `stock.quantity` и `stock.avgCost*`.** Отдельного флага «оприходовано» нет — факт виден по остатку. Продажа возможна при `quantity > 0`.

## 4. Жизненный цикл продажи

**Триггер:** покупатель оформил заказ.

### 4.1. Статусы

`paid` → `shipped` → `received` / `refusal`

| Статус | Что означает |
|---|---|
| `paid` | Покупатель оплатил |
| `shipped` | Передан в доставку |
| `received` | Получен покупателем |
| `refusal` | Отказ / возврат |

`collected` **убран** — избыточен.

### 4.2. Роль маркетплейса

| Функция | Как отражается |
|---|---|
| Приём платежей | `payouts` (пакетные выплаты) |
| Комиссия | `payoutAdjustments` (`adjustmentType = 'commission'`) |
| Доставка | `marketplaceOrderId` для сверки |
| Возвраты | `salesReturns` |
| Потери | `payoutAdjustments` + `stockWriteOffs` |

### 4.3. Шаги

1. Заказ с маркетплейса → `SalesOrder` + позиции. Покупателю присваивается `buyerNickname` (или автогенерация `guest_2026_0001`).
2. Статус → `paid`. `orderDate` = дата оформления.
3. Комплектация: списание со склада. Статус → `shipped`.
4. Доставка.
5. Покупатель получил → `received`. Или отказался → `refusal`.
6. OZON раз в 2 недели перечисляет выплату по совокупности заказов → `payouts` + `payoutAdjustments`.

**Комиссия не хранится в `salesOrders`.** Предварительная оценка — `marketplaces.defaultCommissionRate` на лету. Точная — в `payoutAdjustments` после отчёта OZON.

---

## 5. Предпродажная подготовка

1. Кладовщик увеличивает `stock.countOfRepair` на количество единиц.
2. `availableForSale = quantity − countOfRepair`.
3. После подготовки — уменьшает `countOfRepair`.

`countOfRepair` — свойство склада, не статус заказа.

---

## 6. Консолидация посылок

1. Несколько поставщиков отправляют товары посреднику.
2. Посредник консолидирует в одну `Shipment`.
3. К `Shipment` привязываются все `PurchaseOrder` (валюта должна совпадать).
4. У `Shipment`: `trackNumber`, `carrierId`, `originCountryId`, `deliveryCost`, `customsDuty`.

**Правило:** 1 PO → 1 Shipment (жёстко). 1 Shipment → N PO.

## 7. Потери при закупке (Shipment Losses)

**Триггер:** посылка не дошла целиком/частично.

### 7.1. Полная потеря

1. `shipmentLosses`: `lossType = 'full'`, `lossAmount = Σ(supplierPrice × quantityOrdered)`, `refundReceived` — от ТК/поставщика.
2. Позиции **не приходуются**.
3. `deliveryCost + customsDuty` — в `shipmentLosses` как часть потери.

### 7.2. Частичная потеря (принято хоть что-то)

1. `shipmentLosses`: `lossType = 'partial'`, `lossAmount = Σ(supplierPrice × (quantityOrdered − quantityReceived))`.
2. `refundReceived` = `supplierPrice` потерянных (без overhead).
3. Принятые приходуются. **Overhead распределяется только на принятые** — потерянные не участвуют в `totalShipmentValue`. Это увеличивает landed cost принятых.

### 7.3. Причины (`reason`)

| Причина | Тип | Компенсация |
|---|---|---|
| `customs_rejected` | full/partial | От поставщика/таможни (часто 0) |
| `destroyed` | full/partial | От поставщика/ТК |
| `returned_to_seller` | full/partial | Частичный возврат |
| `lost_in_transit` | full/partial | От ТК |
| `defect` (брак) | partial | От ТК по `supplierPrice` |
| `incomplete` (некомплект) | partial | От ТК по `supplierPrice` |

**Пересортица** — не loss, а корректировка `quantityReceived`.

**Убыток = `lossAmount − refundReceived`.** Отдельная статья, не «размазывается» на себестоимость.

## 8. Возвраты по продаже (Sales Returns)

**Триггер:** покупатель вернул товар, товар **физически вернулся**.

**Ключевое отличие от потерь при доставке:** товар вернулся и может быть продан снова.

### 8.1. Механика

1. `salesReturns`: `returnDate`, `reason`, `refundAmount`, `returnShippingCost`, `returnCondition`, `warehouseId`.
2. `salesOrders` → `refusal`.
3. `stock.quantity += quantity`.
4. `returnCondition IN ('used','damaged')` → `stock.countOfRepair += quantity`.
5. Если не подлежит восстановлению → `stockWriteOffs` (`reason = 'defect_on_return'`).
6. Маркетплейс корректирует выплату → `payoutAdjustments` (`adjustmentType = 'refund'`, отрицательная).

**Убыток** = `refundAmount + returnShippingCost`.

### 8.2. Причины (`reason`)

`customer_refusal` (передумал), `damaged` (повреждён), `wrong_item` (не тот), `not_as_described` (не соответствует).

### 8.3. Потеря при возврате и при прямой доставке (НЕ возврат, а компенсация)

**`lost_in_return`** — товар дошёл, потом вернулся и потерялся. **`lost_in_delivery`** — потерян при доставке покупателю.

В обоих случаях:
- **Товар физически не вернулся** → не `salesReturns`.
- **OZON компенсирует полную стоимость** (как за покупку).
- Товар **списывается** через `stockWriteOffs` (`reason = 'lost_in_delivery'` / `'lost_in_return'`).
- Компенсация — в `payoutAdjustments` (`adjustmentType = 'lost_in_delivery'` / `'lost_in_return'`, **положительная сумма**).

**Разница:**
- `lost_in_delivery` — доставку до потребителя **не оплачиваем** (товар не доставлен).
- `lost_in_return` — доставку **оплатили** (товар был доставлен, потом возвращался).

**Убыток** = `0` (компенсация ≥ себестоимости) или `компенсация − себестоимость`, если меньше.

---

## 9. Списания со склада (Stock Write-Offs)

**Триггер:** товар не подлежит восстановлению.

| Причина (`reason`) | Где возникает |
|---|---|
| `defect_on_receipt` | Брак при приёмке закупки |
| `defect_on_return` | Повреждён при возврате |
| `lost_in_delivery` | Потерян при доставке покупателю (компенсация OZON) |
| `lost_in_return` | Потерян при возврате (компенсация OZON) |

**Механика:** `stock.quantity -= quantity`, `countOfRepair -= quantity` (если был в подготовке). `avgCost*` не меняется. Убыток = `quantity × avgCost*` (если не компенсирован).

## 10. Выплаты маркетплейсов (Payouts)

**OZON перечисляет деньги 2 раза в месяц** по совокупности заказов за период. В выплате — заказы, минус комиссия, минус возвраты, плюс компенсации потерь.

### 10.1. Как формируется

1. OZON присылает отчёт за период.
2. Создаётся `payouts`: `marketplaceId`, `periodStart`, `periodEnd`, `paidAt` (NOT NULL), `totalAmount` (NOT NULL), `reportNumber`.
3. Для каждого заказа в периоде — строки в `payoutAdjustments`.

### 10.2. Типы корректировок (`payoutAdjustments.adjustmentType`)

| Тип | Что означает | Знак |
|---|---|---|
| `order_amount` | Сумма заказа (`saleTotal`) | **+** |
| `commission` | Комиссия маркетплейса | **−** |
| `refund` | Возврат покупателю | **−** |
| `lost_in_delivery` | Компенсация за потерю при доставке | **+** |
| `lost_in_return` | Компенсация за потерю при возврате | **+** |
| `commission_correction` | Корректировка комиссии | ± |
| `other` | Прочее | ± |

### 10.3. Сверка

`payouts.totalAmount = SUM(payoutAdjustments.amount)` для данного `payoutId`.

### 10.4. Что это даёт

- **Точная маржинальность** — после выплаты: `SUM(payoutAdjustments.amount) − SUM(costAtSale × quantity)`.
- **LTV покупателя** — `SUM(payoutAdjustments.amount)` по его заказам.
- **Учёт потерь** — компенсации видны отдельными строками.
- **Сверка с банком** — по `paidAt`.

### 10.5. Ожидаемая выплата

До отчёта OZON **не хранится** — вычисляется на лету: `Σ(saleTotal − saleTotal × defaultCommissionRate)` по заказам с `received`/`refusal` в периоде.

## 11. Ключевые даты для анализа

### 11.1. Закупка

| № | Событие | Где |
|---|---|---|
| 1 | Дата оплаты | `purchaseOrders.orderDate` |
| 2 | Дата поступления в СД | `shipmentStatusHistory.at_carrier` |
| 3 | Дата отправки | `shipmentStatusHistory.shipped` |
| 4 | Дата получения | `shipmentStatusHistory.received` |

**Аналитика:**
- Время от оплаты до СД (`at_carrier − orderDate`) — поставщик + консолидация.
- Время в пути (`received − shipped`) — логистика (по `carrierId`).
- Время на таможне (`customs − shipped`).

### 11.2. Продажа

| № | Событие | Где |
|---|---|---|
| 1 | Дата оплаты | `salesOrderStatusHistory.paid` |
| 2 | Дата отправки | `salesOrderStatusHistory.shipped` |
| 3 | Дата получения / отказа | `salesOrderStatusHistory.received` / `refusal` |
| 4 | Дата возврата товара | `salesReturns.returnDate` |

**Аналитика:**
- Время сборки (`shipped − paid`).
- Время в пути (`received − shipped`).
- Скорость возврата (`returnDate − refusalDate`).
- % возвратов.
- Средний чек.
- Маржинальность (предварительная / точная).
- LTV покупателя.

## 13. Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Статусы закупки | На уровне посылки (`shipmentStatusHistory`), не заказа |
| Статус `collected` | Убран (избыточен) |
| Статус `paid` в истории посылки | Убран. Дата оплаты — `purchaseOrders.orderDate` |
| Overhead (доставка + пошлина) | На все позиции приёмки; при потере — только на принятые |
| Потери закупки | `shipmentLosses`, отдельная статья |
| `lost_in_delivery` / `lost_in_return` | Компенсации OZON, не убытки. `payoutAdjustments` + `stockWriteOffs` |
| Возвраты продажи | `salesReturns` — только если товар физически вернулся |
| Выплаты | `payouts` + `payoutAdjustments`, пакетные (2 раза/мес) |
| Комиссия | Из отчёта OZON (`payoutAdjustments`), не в `salesOrders` |
| Трек-номер | Не уникален (разные службы) |
| Мультивалютные посылки | Нет (одна валюта на посылку) |
| Списание | `stockWriteOffs` с причинами |
