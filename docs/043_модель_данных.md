# Модель данных — часть 4: Продажа

Версия: 0.2
Статус: Черновик
Последнее обновление: 2026-10-23

Продолжение документов `04_модель_данных.md` (часть 1: справочники), `041_модель_данных.md` (часть 2: товары и склад), `042_модель_данных.md` (часть 3: закупка). Здесь описан контур продажи.

> **Ключевые принципы:**
> - **Два независимых контура.** Закупка и продажа не связаны напрямую. Пересечение — только через `stock`.
> - **Продажа возможна при `stock.quantity − stock.countOfRepair > 0`.**
> - **Один заказ на продажу = один маркетплейс, одна валюта (RUB), одна история статусов.**
> - **Минимизация ПД.** В `buyers` — только `buyerNickname`, `buyerCity` (опц.), `buyerAgeGroup` (опц.). ФИО, телефон, email, адрес — **не храним**. При запуске SelfSite — отдельный контур с согласиями.
> - **`costAtSale` может быть `NULL`** — «себестоимость неизвестна». Не заменять нулём.
> - **Выплаты OZON — пакетные** (раз в 2 недели). Отдельная сущность `payouts` + детализация `payoutAdjustments`.
> - **Потери при доставке** (`lost_in_delivery`, `lost_in_return`) — компенсируются OZON, убытка нет. Товар списывается через `stockWriteOffs`.

## 4. Продажа

### 4.1. `buyers` — Покупатели (минимум ПД)

**Назначение:** минимальная информация о покупателе для аналитики LTV. Без персональных данных.

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `buyerId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `buyerNickname` | `VARCHAR(100)` | `NOT NULL`, `UNIQUE` | — | Псевдоним с маркетплейса (или внутренний для SelfSite) |
| `buyerCity` | `VARCHAR(100)` | | — | Город (опционально, если OZON даёт) |
| `buyerAgeGroup` | `VARCHAR(10)` | `CHECK (IN ('18-24','25-34','35-44','45-54','55+'))` | — | Возрастная группа (опционально, если OZON даёт) |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создан |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменён |

**Индексы:**
- `PRIMARY KEY (buyerId)`
- `UNIQUE (buyerNickname)`

**Бизнес-правила:**
- `buyerNickname` — обязателен, если маркетплейс его даёт. Для SelfSite — внутренний ID (может быть `NULL`, если гость).
- `buyerCity`, `buyerAgeGroup` — опциональны. Заполняются, если OZON даёт в выгрузке.
- **ФИО, телефон, email, адрес, паспортные данные — не храним.** Это снижает риск ПД и затраты на защиту.
- При запуске SelfSite — **отдельный контур**: потребуется согласие на обработку ПД, политика конфиденциальности, защита. Фиксируется как будущий риск, не в MVP.
- `buyerId = NULL` в `salesOrders` — только для SelfSite-продаж без регистрации (редкость).

### 4.2. `salesOrders` — Заказы на продажу

**Назначение:** шапка заказа покупателя. Один заказ = один покупатель (или гость), один маркетплейс, одна валюта (RUB).

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `salesOrderId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `buyerId` | `INTEGER` | `REFERENCES buyers(buyerId)` | — | Покупатель. `NULL` — гостевая покупка (SelfSite без регистрации) |
| `marketplaceId` | `SMALLINT` | `NOT NULL`, `REFERENCES marketplaces(marketplaceId)` | — | Маркетплейс (OZON, Avito, WB, YM, VK, SelfSite) |
| `marketplaceOrderId` | `VARCHAR(100)` | | — | Номер заказа на маркетплейсе (для сверки). Может быть `NULL` |
| `currencyId` | `SMALLINT` | `NOT NULL`, `REFERENCES currencies(currencyId)` | — | Валюта продажи (по умолчанию RUB) |
| `orderDate` | `DATE` | `NOT NULL` | — | Дата оформления заказа |
| `commissionRate` | `NUMERIC(5,4)` | `NOT NULL`, `CHECK (>= 0 AND <= 1)` | — | Фактическая комиссия маркетплейса (дефолт из `marketplaces`, правится вручную) |
| `commissionAmount` | `NUMERIC(12,2)` | `CHECK (commissionAmount >= 0)` | — | Сумма комиссии (`saleTotal × commissionRate`). Вычисляется |
| `payoutId` | `INTEGER` | `REFERENCES payouts(payoutId)` | — | Выплата, в которую входит заказ. `NULL` — пока не выплачен |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создан |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменён |

**Индексы:**
- `PRIMARY KEY (salesOrderId)`
- `INDEX (buyerId)` — для отчёта «покупки покупателя»
- `INDEX (marketplaceId)` — для отчёта «продажи по маркетплейсу»
- `INDEX (orderDate)` — для отчёта «продажи за период»
- `INDEX (payoutId)` — для отчёта «заказы в выплате»
- `INDEX (marketplaceOrderId)` — для сверки с маркетплейсом

**Бизнес-правила:**
- `buyerId = NULL` — только SelfSite без регистрации. Для маркетплейсов `buyerNickname` обычно есть.
- `commissionRate` — дефолт из `marketplaces.defaultCommissionRate`. Может быть изменён вручную.
- `commissionAmount = saleTotal × commissionRate`, где `saleTotal = SUM(salePrice × quantity)` по позициям. Вычисляется при сохранении.
- `payoutId` — `NULL`, пока заказ не вошёл в выплату. При включении в выплату — заполняется.
- **`payoutAmount` не хранится** — вычисляется как `saleTotal − commissionAmount` (или берётся из `payoutAdjustments`).

### 4.3. `salesOrderItems` — Позиции заказа на продажу

**Назначение:** строки заказа. Один товар + количество + цена продажи. При продаже — списание со склада.

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `salesOrderItemId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `salesOrderId` | `INTEGER` | `NOT NULL`, `REFERENCES salesOrders(salesOrderId) ON DELETE CASCADE` | — | Заказ |
| `goodId` | `INTEGER` | `NOT NULL`, `REFERENCES goods(goodId) ON DELETE RESTRICT` | — | Товар |
| `quantity` | `INTEGER` | `NOT NULL`, `CHECK (quantity > 0)` | — | Количество проданных единиц |
| `salePrice` | `NUMERIC(12,2)` | `NOT NULL`, `CHECK (salePrice >= 0)` | — | Цена за единицу при продаже (в валюте заказа) |
| `costAtSale` | `NUMERIC(12,2)` | `CHECK (costAtSale >= 0)` | — | Себестоимость единицы на момент продажи (`stock.avgCostRub`). `NULL` — себестоимость неизвестна |
| `warehouseId` | `SMALLINT` | `NOT NULL`, `REFERENCES warehouses(warehouseId)` | — | С какого склада списан товар |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменена |

**Индексы:**
- `PRIMARY KEY (salesOrderItemId)`
- `INDEX (salesOrderId)` — для выборки позиций заказа
- `INDEX (goodId)` — для отчёта «продажи по товару»
- `INDEX (warehouseId)` — для отчёта «продажи со склада»

**Бизнес-правила:**
- `quantity > 0`.
- `salePrice` — цена продажи за единицу.
- **`costAtSale`** — `stock.avgCostRub` на момент продажи. Фиксируется, чтобы маржинальность не «плыла» при следующих закупках. Если `stock.avgCostRub IS NULL` — `costAtSale = NULL`. В отчётах — «нет данных о себестоимости».
- `warehouseId` — с какого склада списан товар. Для MVP — `main`.
- **Списание со склада:** при создании позиции (или при смене статуса на `shipped`) — `stock.quantity -= quantity`. Проверка: `stock.quantity − stock.countOfRepair >= quantity`.

### 4.4. `salesOrderStatusHistory` — История статусов заказа

**Назначение:** все переходы статусов заказа с датой. Текущий статус — последняя запись.

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `historyId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `salesOrderId` | `INTEGER` | `NOT NULL`, `REFERENCES salesOrders(salesOrderId) ON DELETE CASCADE` | — | Заказ |
| `statusId` | `SMALLINT` | `NOT NULL`, `REFERENCES statuses(statusId)` | — | Статус (из `statuses`, где `statusType = 'sale'`) |
| `statusDate` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда статус установлен |
| `comment` | `TEXT` | | — | Комментарий. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда запись создана |

**Индексы:**
- `PRIMARY KEY (historyId)`
- `INDEX (salesOrderId, statusDate)` — для выборки истории
- `INDEX (statusId)` — для отчёта «сколько заказов в статусе X»

**Статусы заказа:**

| № | `statusName` | Что означает | Ключевая дата |
|---|---|---|---|
| 1 | `paid` | Покупатель оплатил заказ | **Дата оплаты** |
| 2 | `shipped` | Передан в доставку | **Дата отправки** |
| 3 | `received` | Покупатель получил заказ | **Дата получения** |
| 4 | `refusal` | Покупатель отказался / вернул | **Дата отказа** |

`collected` **убран** — избыточен.

### 4.5. `salesReturns` — Возвраты товара

**Назначение:** возвраты, при которых **товар физически вернулся** на склад (`returnedToStock = TRUE`). Потери при доставке (`lost_in_delivery`, `lost_in_return`) — **не здесь**, а в `payoutAdjustments` + `stockWriteOffs` (товар не вернулся).

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `returnId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `salesOrderId` | `INTEGER` | `NOT NULL`, `REFERENCES salesOrders(salesOrderId) ON DELETE RESTRICT` | — | Заказ |
| `returnDate` | `DATE` | `NOT NULL` | — | Дата возврата |
| `reason` | `VARCHAR(50)` | `NOT NULL`, `CHECK (IN ('customer_refusal','damaged','wrong_item','not_as_described'))` | — | Причина возврата |
| `refundAmount` | `NUMERIC(12,2)` | `CHECK (refundAmount >= 0)` | `0` | Сумма, возвращённая покупателю |
| `returnShippingCost` | `NUMERIC(12,2)` | `CHECK (returnShippingCost >= 0)` | `0` | Стоимость обратной доставки (если на нас) |
| `returnCondition` | `VARCHAR(20)` | `CHECK (IN ('new','used','damaged'))` | — | Состояние товара при возврате |
| `warehouseId` | `SMALLINT` | `NOT NULL`, `REFERENCES warehouses(warehouseId)` | — | На какой склад возвращён товар |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменена |

**Индексы:**
- `PRIMARY KEY (returnId)`
- `INDEX (salesOrderId)` — для отчёта «возвраты по заказу»
- `INDEX (returnDate)` — для отчёта «возвраты за период»
- `INDEX (reason)` — для отчёта «причины возвратов»

**Бизнес-правила:**
- `returnedToStock = TRUE` — всегда (для этой таблицы). Товар физически вернулся.
- `returnCondition`:
  - `new` — товар как новый, можно продавать сразу.
  - `used` — требует подготовки (`stock.countOfRepair += quantity`).
  - `damaged` — требует подготовки или списания (если не подлежит восстановлению — `stockWriteOffs`).
- `stock.quantity += quantity` (количество возвращённого товара).
- `salesOrders` → статус `refusal`.
- Если `returnCondition IN ('used','damaged')` — `stock.countOfRepair += quantity`.
- Если товар не подлежит восстановлению — `stockWriteOffs` (см. 4.7).

### 4.6. `payouts` — Выплаты маркетплейсов

**Назначение:** пакетные выплаты от маркетплейса. OZON перечисляет деньги **раз в 2 недели** по совокупности заказов. В выплате — совокупность заказов, минус возвраты, минус потери, плюс компенсации.

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `payoutId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `marketplaceId` | `SMALLINT` | `NOT NULL`, `REFERENCES marketplaces(marketplaceId)` | — | Маркетплейс |
| `periodStart` | `DATE` | `NOT NULL` | — | Начало периода (например, 1-е число) |
| `periodEnd` | `DATE` | `NOT NULL` | — | Конец периода (например, 15-е число) |
| `paidAt` | `DATE` | | — | Дата фактического перечисления (для сверки с банковской выпиской). Может быть `NULL` |
| `totalAmount` | `NUMERIC(12,2)` | `CHECK (totalAmount >= 0)` | — | Фактически перечисленная сумма. Может быть `NULL`, пока не известна |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменена |

**Индексы:**
- `PRIMARY KEY (payoutId)`
- `INDEX (marketplaceId)` — для отчёта «выплаты по маркетплейсу»
- `INDEX (periodStart, periodEnd)` — для отчёта «выплаты за период»
- `INDEX (paidAt)` — для сверки с банком

**Бизнес-правила:**
- `periodStart`, `periodEnd` — период, в котором заказ **оплачен и получен/отказ** (действие по отношению к покупателю завершено). То есть в выплату попадают заказы, у которых `received` или `refusal` в этом периоде.
- `paidAt` — дата фактического перечисления. Для сверки с банковской выпиской (интеграция — не в MVP, но поле есть).
- `totalAmount` — фактически перечисленная сумма. Может отличаться от «расчётной» (из-за корректировок).
- `payouts` — шапка. Детализация — в `payoutAdjustments`.

### 4.7. `payoutAdjustments` — Детализация выплаты по заказам

**Назначение:** какие заказы вошли в выплату, какие корректировки по каждому заказу (возврат, потеря, компенсация). Позволяет считать потери по каждому заказу.

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `adjustmentId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `payoutId` | `INTEGER` | `NOT NULL`, `REFERENCES payouts(payoutId) ON DELETE CASCADE` | — | Выплата |
| `salesOrderId` | `INTEGER` | `NOT NULL`, `REFERENCES salesOrders(salesOrderId) ON DELETE RESTRICT` | — | Заказ |
| `adjustmentType` | `VARCHAR(30)` | `NOT NULL`, `CHECK (IN ('order_amount','refund','lost_in_delivery','lost_in_return','commission_correction','other'))` | — | Тип корректировки |
| `amount` | `NUMERIC(12,2)` | `NOT NULL` | — | Сумма. Положительная — нам, отрицательная — удержание |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана |

**Индексы:**
- `PRIMARY KEY (adjustmentId)`
- `INDEX (payoutId)` — для выборки корректировок выплаты
- `INDEX (salesOrderId)` — для отчёта «корректировки по заказу»
- `INDEX (adjustmentType)` — для отчёта «причины корректировок»

**Типы корректировок:**

| `adjustmentType` | Что означает | Знак `amount` |
|---|---|---|
| `order_amount` | Сумма заказа (saleTotal − commission) | Положительная |
| `refund` | Возврат покупателю (из `salesReturns`) | Отрицательная |
| `lost_in_delivery` | Потеря при прямой доставке. OZON компенсирует полную стоимость. **Доставку до потребителя мы не оплачиваем** | Положительная (компенсация) |
| `lost_in_return` | Потеря при возврате. Товар дошёл, потом вернулся и потерялся. **Доставку до потребителя мы оплатили** (в заказе). OZON компенсирует полную стоимость | Положительная (компенсация) |
| `commission_correction` | Корректировка комиссии (если OZON пересчитал) | Любая |
| `other` | Прочее | Любая |

**Бизнес-правила:**
- Один заказ может иметь несколько корректировок (order_amount + refund + lost_in_return).
- Сумма выплаты = `SUM(amount)` по всем `payoutAdjustments` для данного `payoutId`.
- `lost_in_delivery` / `lost_in_return` — **компенсации от OZON**, не убытки. Товар списывается через `stockWriteOffs` (см. 4.8).
- **Расчёт потерь по заказу:** `lost_in_delivery` и `lost_in_return` — положительные суммы (компенсации). Если компенсация < себестоимости — разница = убыток. Если компенсация ≥ себестоимости — убытка нет.

### 4.8. `stockWriteOffs` — Списания со склада

**Назначение:** списание товара, не подлежащего восстановлению. Возникает при:
- Приёмке закупки — брак (`reason = 'defect_on_receipt'`).
- Приёмке возврата от покупателя — повреждён (`reason = 'defect_on_return'`).
- Потере при доставке — (`reason = 'lost_in_delivery'` / `'lost_in_return'`).

**Таблица описана в части 2 (`041_модель_данных.md`), здесь — ссылка для контекста продажи.**

| Поле | Тип | Описание |
|---|---|---|
| `writeOffId` | `SERIAL` PK | ID списания |
| `goodId` | `INTEGER` FK | Товар |
| `warehouseId` | `SMALLINT` FK | Склад |
| `quantity` | `INTEGER` | Количество списанных единиц |
| `reason` | `VARCHAR(50)` | `defect_on_receipt`, `defect_on_return`, `lost_in_delivery`, `lost_in_return`, `other` |
| `sourceType` | `VARCHAR(20)` | `purchase_receipt`, `sales_return`, `sales_delivery`, `manual` |
| `sourceId` | `INTEGER` | ID источника (purchaseOrderItemId, salesReturnId, salesOrderId) |
| `writeOffDate` | `DATE` | Дата списания |
| `notes` | `TEXT` | |
| `createdAt`, `updatedAt` | | Аудит |

**Логика:**
- `stock.quantity -= quantity`, `stock.countOfRepair -= quantity` (если товар был в подготовке).
- `stock.avgCost*` не меняется (себестоимость списанного — убыток, если не компенсирован).
- Для `lost_in_delivery` / `lost_in_return` — списание, но **не убыток** (компенсация OZON в `payoutAdjustments`).

## Ключевые даты для анализа (продажа)

| № | Событие | Где хранится |
|---|---|---|
| 1 | Дата оплаты | `salesOrders.orderDate` (или `statusDate` статуса `paid`) |
| 2 | Дата отправки | `salesOrderStatusHistory` (`shipped`) |
| 3 | Дата получения / отказа | `salesOrderStatusHistory` (`received` / `refusal`) |
| 4 | **Дата возврата товара** | `salesReturns.returnDate` |

**Аналитика:**
- Время от оплаты до отправки (`shipped − paid`) — скорость сборки.
- Время в пути (`received − shipped`) — логистика.
- Время от отказа до возврата (`returnDate − refusalDate`) — скорость возврата.
- Процент возвратов (`COUNT(salesReturns) / COUNT(salesOrders)`).
- Средний чек (`AVG(saleTotal)`).
- Маржинальность (`saleTotal − commissionAmount − SUM(costAtSale × quantity)`) — только по позициям с `costAtSale IS NOT NULL`.
- Доля позиций без себестоимости (прозрачность).

## Изменения в части 2 (`041_модель_данных.md`) — `stock` и `stockWriteOffs`

### `stock` — добавить `avgCostUpdatedAt`

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `avgCostUpdatedAt` | `DATE` | | — | Дата последнего обновления себестоимости. **`2026-09-01`** — флаг «миграционная цена внесена вручную». Дата приёмки — цена рассчитана из закупки |

**Бизнес-правила:**
- `avgCostUpdatedAt = 2026-09-01` — цена «ручная», требует пересмотра.
- `avgCostUpdatedAt = дата приёмки` — цена рассчитана из закупки.
- В интерфейсе — фильтр «товары с миграционной ценой».
