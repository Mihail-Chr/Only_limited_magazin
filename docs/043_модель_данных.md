# Модель данных — часть 4: Продажа

Версия: 1.0
Статус: Черновик
Последнее обновление: 2026-10-23

Продолжение `04_модель_данных.md` (часть 1), `041_модель_данных.md` (часть 2), `042_модель_данных.md` (часть 3). Здесь — контур продажи.

> **Ключевые принципы:**
> - **Два независимых контура.** Пересечение — только через `stock`.
> - **Продажа при `stock.quantity − stock.countOfRepair > 0`.**
> - **Один заказ = один маркетплейс, одна валюта (RUB).**
> - **Минимизация ПД.** `buyers`: только `buyerNickname`, `buyerCity` (опц.), `buyerAgeGroup` (опц.). ФИО/телефон/email/адрес — не храним. SelfSite — отдельный контур (фаза 2).
> - **`buyerNickname NOT NULL UNIQUE`.** Гостям — автогенерация (`guest_2026_0001`). `salesOrders.buyerId NOT NULL`.
> - **`costAtSale` может быть `NULL`** — «себестоимость неизвестна».
> - **Комиссия в `salesOrders` не хранится.** Всё в `payoutAdjustments` (`adjustmentType = 'commission'`). Предварительная оценка — `marketplaces.defaultCommissionRate` на лету.
> - **`payouts` — по факту отчёта OZON.** `paidAt`, `totalAmount` — `NOT NULL`.
> - **`lost_in_delivery` / `lost_in_return`** — компенсации OZON, не убытки. Товар списывается через `stockWriteOffs`.
> - **`collected` убран.** Цепочка: `paid` → `shipped` → `received` / `refusal`.

## 4. Продажа

### 4.1. `buyers` — Покупатели (минимум ПД)

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `buyerId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `buyerNickname` | `VARCHAR(100)` | `NOT NULL`, `UNIQUE` | — | Псевдоним с маркетплейса. Для SelfSite-гостей — автогенерация (`guest_2026_0001`) |
| `buyerCity` | `VARCHAR(100)` | | — | Город (опц., если OZON даёт) |
| `buyerAgeGroup` | `VARCHAR(10)` | `CHECK (IN ('18-24','25-34','35-44','45-54','55+'))` | — | Возрастная группа (опц.) |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создан |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменён |

**Индексы:** PK, `UNIQUE (buyerNickname)`.

**Бизнес-правила:**
- `buyerNickname` — **всегда обязателен**. Гостям — автогенерация. Все заказы привязаны к покупателю, LTV для всех.
- ФИО, телефон, email, адрес, паспорт — **не храним**. Снижает риск ПД.
- При запуске SelfSite — **отдельный контур**: согласие на обработку ПД, политика, защита. Не в MVP.

| `orderDate` | `DATE` | `NOT NULL` | — | Дата оформления заказа |
| `payoutId` | `INTEGER` | `REFERENCES payouts(payoutId)` | — | Выплата. `NULL` — пока не выплачен |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создан |

**Бизнес-правила:**
- `buyerId NOT NULL`. Гостям — автогенерация.
- `payoutId = NULL`, пока не в выплате.
- **Сумма заказа не хранится** — `SUM(salePrice × quantity)` по позициям.
- **Комиссия не хранится** — в `payoutAdjustments`. Для предварительной оценки — `marketplaces.defaultCommissionRate` на лету.

|---|---|---|---|---|
| `salesOrderItemId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `salesOrderId` | `INTEGER` | `NOT NULL`, `REFERENCES salesOrders(salesOrderId) ON DELETE CASCADE` | — | Заказ |

| `salePrice` | `NUMERIC(12,2)` | `NOT NULL`, `CHECK (salePrice >= 0)` | — | Цена за единицу |
| `costAtSale` | `NUMERIC(12,2)` | `CHECK (costAtSale >= 0)` | — | Себестоимость единицы на момент продажи (`stock.avgCostRub`). `NULL` — неизвестна |
| `warehouseId` | `SMALLINT` | `NOT NULL`, `REFERENCES warehouses(warehouseId)` | — | С какого склада списан |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменена |

**Индексы:** PK, `INDEX (salesOrderId)`, `INDEX (goodId)`, `INDEX (warehouseId)`.

**Бизнес-правила:**
- `costAtSale` — `stock.avgCostRub` на момент продажи. Фиксируется. Если `NULL` — «нет данных».
- Списание со склада: `stock.quantity -= quantity`. Проверка: `stock.quantity − stock.countOfRepair >= quantity`.

### 4.5. `salesReturns` — Возвраты товара

**Назначение:** возвраты, при которых **товар физически вернулся**. Потери при доставке — в `payoutAdjustments` + `stockWriteOffs`.

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `returnId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `salesOrderId` | `INTEGER` | `NOT NULL`, `REFERENCES salesOrders(salesOrderId) ON DELETE RESTRICT` | — | Заказ |
| `returnDate` | `DATE` | `NOT NULL` | — | Дата возврата |
| `reason` | `VARCHAR(50)` | `NOT NULL`, `CHECK (IN ('customer_refusal','damaged','wrong_item','not_as_described'))` | — | Причина |
| `refundAmount` | `NUMERIC(12,2)` | `CHECK (refundAmount >= 0)` | `0` | Сумма возврата покупателю |
| `returnShippingCost` | `NUMERIC(12,2)` | `CHECK (returnShippingCost >= 0)` | `0` | Стоимость обратной доставки |
| `returnCondition` | `VARCHAR(20)` | `NOT NULL`, `CHECK (IN ('new','used','damaged'))` | — | Состояние товара |
| `warehouseId` | `SMALLINT` | `NOT NULL`, `REFERENCES warehouses(warehouseId)` | — | На какой склад возвращён |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменена |

**Индексы:** PK, `INDEX (salesOrderId)`, `INDEX (returnDate)`, `INDEX (reason)`.

**Бизнес-правила:**
- Товар физически вернулся (`returnedToStock = TRUE` — подразумевается).
- `returnCondition = 'new'` — можно продавать сразу.
- `'used'` / `'damaged'` — `stock.countOfRepair += quantity`.
- Если не подлежит восстановлению — `stockWriteOffs` (`reason = 'defect_on_return'`).
- `stock.quantity += quantity`.
- `salesOrders` → `refusal`.
- Убыток = `refundAmount + returnShippingCost`.

### 4.6. `payouts` — Выплаты маркетплейсов

**Назначение:** пакетные выплаты от маркетплейса (OZON — раз в 2 недели). Создаётся **по факту отчёта OZON**.

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `payoutId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `marketplaceId` | `SMALLINT` | `NOT NULL`, `REFERENCES marketplaces(marketplaceId)` | — | Маркетплейс |
| `periodStart` | `DATE` | `NOT NULL` | — | Начало периода (1-е или 15-е) |
| `periodEnd` | `DATE` | `NOT NULL` | — | Конец периода |
| `paidAt` | `DATE` | **`NOT NULL`** | — | Дата фактического перечисления (из отчёта OZON) |
| `totalAmount` | `NUMERIC(12,2)` | **`NOT NULL`**, `CHECK (totalAmount >= 0)` | — | Фактически перечисленная сумма (из отчёта OZON) |
| `reportNumber` | `VARCHAR(50)` | | — | Номер отчёта OZON (для сверки). Опционально |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана |
| `updatedAt` | `TIMESTAMP` | | — | Когда изменена |

**Индексы:** PK, `INDEX (marketplaceId)`, `INDEX (periodStart, periodEnd)`, `INDEX (paidAt)`.

**Бизнес-правила:**
- `periodStart`–`periodEnd` — период, в котором заказ **оплачен и получен/отказ** (действие завершено).
- `paidAt`, `totalAmount` — **`NOT NULL`**, из отчёта OZON.
- «Ожидаемая выплата» — вычисляется на лету, не хранится.
- Сверка: `totalAmount = SUM(payoutAdjustments.amount)` для данного `payoutId`.

### 4.7. `payoutAdjustments` — Детализация выплаты по заказам

| Поле | Тип | Ограничения | По умолчанию | Описание |
|---|---|---|---|---|
| `adjustmentId` | `SERIAL` | `PRIMARY KEY` | автоинкремент | Уникальный идентификатор |
| `payoutId` | `INTEGER` | `NOT NULL`, `REFERENCES payouts(payoutId) ON DELETE CASCADE` | — | Выплата |
| `salesOrderId` | `INTEGER` | `NOT NULL`, `REFERENCES salesOrders(salesOrderId) ON DELETE RESTRICT` | — | Заказ |
| `adjustmentType` | `VARCHAR(30)` | `NOT NULL`, `CHECK (IN ('order_amount','commission','refund','lost_in_delivery','lost_in_return','commission_correction','other'))` | — | Тип |
| `amount` | `NUMERIC(12,2)` | `NOT NULL` | — | Сумма. `+` нам, `−` удержание |
| `notes` | `TEXT` | | — | Заметки. Опционально |
| `createdAt` | `TIMESTAMP` | `NOT NULL` | `NOW()` | Когда создана |

**Индексы:** PK, `INDEX (payoutId)`, `INDEX (salesOrderId)`, `INDEX (adjustmentType)`.

**Типы:**

| `adjustmentType` | Что означает | Знак `amount` |
|---|---|---|
| `order_amount` | Сумма заказа (`saleTotal`) | **+** |
| `commission` | Комиссия маркетплейса | **−** |
| `refund` | Возврат покупателю (из `salesReturns`) | **−** |
| `lost_in_delivery` | Потеря при прямой доставке. Доставку до потребителя не оплачиваем. OZON компенсирует полную стоимость | **+** (компенсация) |
| `lost_in_return` | Потеря при возврате. Доставку до потребителя оплатили. OZON компенсирует полную стоимость | **+** (компенсация) |
| `commission_correction` | Корректировка комиссии | Любая |
| `other` | Прочее | Любая |

**Бизнес-правила:**
- Один заказ — несколько корректировок (`order_amount` + `commission` + `refund` + ...).
- `payouts.totalAmount = SUM(amount)`.
- **Комиссия — только здесь.** В `salesOrders` не хранится.
- `lost_in_delivery` / `lost_in_return` — компенсации, не убытки. Товар списывается через `stockWriteOffs`.
- Убыток = `компенсация − себестоимость`, если компенсация < себестоимости.

**Пример:**

| `payoutId` | `salesOrderId` | `adjustmentType` | `amount` |
|---|---|---|---|
| 1 | 100 | `order_amount` | +5000.00 |
| 1 | 100 | `commission` | −2250.00 |
| 1 | 101 | `order_amount` | +3000.00 |
| 1 | 101 | `commission` | −1350.00 |
| 1 | 101 | `refund` | −3000.00 |
| 1 | 102 | `order_amount` | +4000.00 |
| 1 | 102 | `commission` | −1800.00 |
| 1 | 102 | `lost_in_delivery` | +4000.00 |
| **Итого** | | | **7600.00** |

`payouts.totalAmount = 7600.00` (из отчёта). Сверка: `SUM(amount) = 7600.00`.

## Ключевые даты для анализа (продажа)

| № | Событие | Где хранится |
|---|---|---|
| 1 | Дата оплаты | `salesOrders.orderDate` (или `statusDate` статуса `paid`) |
| 2 | Дата отправки | `salesOrderStatusHistory` (`shipped`) |
| 3 | Дата получения / отказа | `salesOrderStatusHistory` (`received` / `refusal`) |
| 4 | **Дата возврата товара** | `salesReturns.returnDate` |

**Аналитика:**
- Время от оплаты до отправки (`shipped − paid`) — скорость сборки.
- Время в пути (`received − shipped`) — логистика.
- Время от отказа до возврата (`returnDate − refusalDate`).
- Процент возвратов.
- Средний чек.
- Маржинальность (предварительная): `saleTotal − saleTotal × defaultCommissionRate − SUM(costAtSale × quantity)`.
- Маржинальность (точная): `SUM(payoutAdjustments.amount) − SUM(costAtSale × quantity)`.
- LTV покупателя: `SUM(payoutAdjustments.amount)` по всем заказам покупателя.
